# 性能测量报告

> 测量时间：2026-11-12 02:41　|　Python 3.12.10　|　Chrome（本机安装版本，headless）

全部数值为实测，不含估算。页面指标取本机 Chrome 冷启动 1 次 + 热缓存多次的中位数，实际网络环境下会受带宽影响；同一机器连续多次运行也可能有 10%–20% 波动。

测量环境基准：空白页 rAF 上限 61 fps（用于判断限速来自环境还是页面）。

## 二、页面加载

| 页面 | 冷启动 FCP | 冷启动 load | 热缓存 FCP | 热缓存 load | 帧率（最优/区间） | 相对环境基准 | 资源数 | 传输体积 |
|---|---|---|---|---|---|---|---|---|
| 主页 | 496 ms | 350 ms | 56 ms | 134 ms | 60（60–60）fps | 98% | 14 | 0.24 MB |
| 3D 元素周期表 | 1044 ms | 1274 ms | 120 ms | 32 ms | 61（61–61）fps | 99% | 5 | 0.33 MB |
| 方程式词云 | 140 ms | 624 ms | 128 ms | 62 ms | 60（59–60）fps | 98% | 6 | 1.47 MB |
| 3D 虚拟实验室 | 528 ms | 25 ms | 60 ms | 15 ms | - | - | 2 | 0.21 MB |
| 化学史诗 | 244 ms | 495 ms | 412 ms | 340 ms | - | - | 7 | 11.41 MB |
| 小游戏合集 | 108 ms | 131 ms | 44 ms | 104 ms | 61（60–61）fps | 99% | 2 | 0.02 MB |

FCP 是浏览器首次绘制出内容的时间，用户感知的「打开就有画面」；load 是全部资源（含背景视频、3D 模型）就绪的时间。热缓存代表二次访问体验。冷启动下 load 早于 FCP 是正常现象：说明资源先下载完，但首屏绘制被样式表或视频首帧推迟了。

> 帧率采样方式：每次加载后 0.8 秒开始采样 1 秒，重复 4 次取最优值。headless Chrome 的 rAF 会随页面静置时间衰减（实测 1–2 秒后降到 30Hz），因此取多轮中的最佳窗口，更接近真实渲染能力；表内括号为各轮区间。「相对环境基准」= 页面帧率 / 空白页 rAF 上限，接近 100% 说明页面已跑满环境上限、瓶颈不在页面本身。测试机为集成显卡，换设备会有差异，不应外推为所有环境的表现。页面若无 canvas（如实验室需进入分区才创建画布），记 `-`。

### 帧率优化记录

背景螺旋粒子曾是该页的主要瓶颈：6000 个 DOM 节点各跑一条 `requestAnimationFrame`，逐帧写入 `left` / `top`，每帧触发数千次样式计算与布局，实测帧率仅 16 fps；隐藏粒子容器后回升到约 40 fps，仅隐藏 canvas 则无变化，据此排除 WebGL 与绘制因素。

修复分两步：先把粒子合并到一条 rAF 批量更新、改用 `transform: translate3d()`（回到 61 fps，但粒子只有 400 颗，观感偏稀）；随后整体迁移到单个 canvas —— 桌面 5200 颗、六臂螺旋，绘制用 `fillRect` 代替 `arc` 路径、只给三成粒子加拖尾，既把粒子密度做足又保持流畅。本次实测 61 fps。

## 三、复现方式

```bash
# 后端算法 + 页面加载
.\\.venv\\Scripts\\python.exe server/benchmark.py

# 只测后端（无需浏览器）
.\\.venv\\Scripts\\python.exe server/benchmark.py --skip-pages

# 追加一次真实 AI 对话（需要密钥）
.\\.venv\\Scripts\\python.exe server/benchmark.py --with-ai
```

页面测量使用本机已安装的 Chrome，无需下载浏览器内核；未安装 Playwright 时自动跳过页面部分，只输出后端数据。
